## Основные команды (Essential commands)

Ниже приведены наиболее востребованные команды для ежедневной работы. Доступность зависит от вашей версии, провайдера и тарифного плана. Полный перечень находится в [§10.1 руководства](./ultimate-guide.md#101-commands-table), а официальная документация — на [code.claude.com/docs/en/commands](https://code.claude.com/docs/en/commands).

| Команда | Действие |
|---------|----------|
| `/help` | Контекстная справка по командам |
| `/powerup` | Интерактивные анимированные уроки по возможностям Claude Code |
| `/clear` | Сбросить текущий диалог и очистить контекст |
| `/compact` | Сжать контекст для освобождения токенов |
| `/status` | Настройки во вкладке Status: версия, модель, аккаунт, сеть |
| `/context` | Детальная разбивка использования токенов контекста |
| `/plan` | Войти в режим планирования Plan Mode (без изменений файлов). Выход: подтверждение плана или `Shift+Tab` |
| `/model` | Выбрать модель и сохранить по умолчанию; клавиша `s` в меню выбора применит модель только на текущую сессию |
| `/autocompact [auto\|500k]` | Настроить окно авто-компактизации или вернуть значение по умолчанию |
| `/output-style [style]` | Выбрать стиль вывода: Default, Proactive, Concise, Explanatory, Learning или кастомный |
| `/insights` | Аналитика использования + отчет по оптимизации |
| `/code-review [level]` | Проверка диффа на баги корректности; флаг `--fix` применяет исправления, `ultra` запускает ревью в облаке |
| `/simplify` | Ревью только для очистки измененного кода: упрощение, повторное использование, эффективность (применяет правки очистки; для багов используйте `/code-review`) |
| `/security-review` | Сканирование диффа ветки на уязвимости (инъекции, авторизация, утечки данных) |
| `/batch` | Крупномасштабный рефакторинг с помощью 5–30 параллельных worktree-агентов |
| `/subtask <task>` | Передать изолированную подзадачу ответвленному подагенту (forked subagent), который вернет результат в текущую сессию (v2.1.212+) |
| `/teleport` | Телепортировать сессию из веб-интерфейса |
| `/tasks` | Мониторинг фоновых задач |
| `/remote-env` | Настроить облачное окружение |
| `/remote-control` (`/rc`) | Подключить локальную сессию к веб-версии или мобильному приложению; в Team/Enterprise требует разрешения владельца |
| `/mobile` | QR-код для загрузки мобильного приложения Claude |
| `/fast` | Переключить режим Fast Mode на моделях Fable 5.2 ($16/$80 за MTok) и Opus 5.5 ($8/$40); Opus 5 и Opus 4.8 ($10/$50) в режиме research preview. Поддержка fast mode в Opus 4.8 завершается 30 ноября 2026 г. Недоступно на Sonnet/Haiku |
| `/voice [hold\|tap\|off]` | Голосовой ввод (удерживайте Пробел, чтобы говорить, отпустите для отправки). Требует аккаунт Claude.ai |
| `/recap` | Однострочное резюме текущей сессии по запросу (v2.1.108) |
| `/effort [level\|auto\|status\|ultracode [on\|off]]` | Уровень усилий рассуждений: low/medium/high/xhigh/max (max только на сессию) или auto; `status` выводит текущий уровень (v2.1.111) |
| `/tui [classic\|fullscreen]` | Задать рендерер интерфейса; `fullscreen` работает без мерцания (v2.1.110), `classic` заменяет `default` (v2.1.327) |
| `/focus` | Переключить минималистичный режим фокуса (только в fullscreen-рендере), отдельно от Ctrl+O (v2.1.110) |
| `/auto-mode-setup` | Интерактивная настройка: анализирует проект и недавние сессии для калибровки auto mode под ваше окружение |
| `/fewer-permission-prompts` | Анализирует логи сессий и предлагает белый список инструментов для чтения (ранее `/less-permission-prompts`) |
| `/btw [question]` | Быстрый вопрос на полях: эфемерный агент в режиме только чтения, не засоряет историю, без инструментов |
| `/loop [interval] [prompt]` | Повторять задачу с фиксированным интервалом (или дать Claude выбрать интервал). Работает до 30 дней, пока открыта сессия (v2.1.330) |
| `/usage` (`/cost`, `/stats`) | Расход токенов и затраты по моделям, лимиты тарифа, график активности (объединены в v2.1.118) |
| `/ultrareview` | Мульти-агентное облачное код-ревью (алиас `/code-review ultra`, v2.1.114). Флаг `--max-findings <n>\|all` ограничивает число замечаний |
| `/goal [condition\|clear]` | Автономный многошаговый режим: Claude работает до выполнения условия; оверлей показывает время/шаги/токены (v2.1.139) |
| `/scroll-speed` | Настройка скорости прокрутки колесика мыши (полноэкранный режим) |
| `/rename [name]` | Назвать или переименовать текущую сессию |
| `/copy [N]` | Скопировать N-й ответ с конца; диалог выбора блока кода или всего ответа |
| `/doctor` | Полная диагностика: установка, настройки, хуки, размер `CLAUDE.md`, неиспользуемые навыки (v2.1.205+). Подкоманда `prompt-audit` проверяет устаревшие паттерны |
| `/debug` | Включить подробный отладочный лог сессии |
| `/exit` | Выход из Claude Code (или `Ctrl+D`) |

## Режимы разрешений (Permission modes)

| Режим | Редактирование файлов | Выполнение команд в Bash |
|-------|-----------------------|--------------------------|
| Manual (`default`) | Действуют правила разрешений | Запрашивает подтверждение |
| acceptEdits | Автоматически | Запрашивает подтверждение |
| Plan Mode | Без изменения файлов | Только команды исследования в режиме чтения |
| auto | Классификатор решает сам | Классификатор решает сам |
| dontAsk | Только если есть в allow rules | Только если есть в allow rules |
| bypassPermissions | Автоматически | Автоматически (только для CI/CD!) |

Переключение режимов: **Shift+Tab**. Интерактивные сессии по умолчанию запускаются в режиме `auto`. Настроить классификатор можно командой `/auto-mode-setup`.

## Стандартный рабочий процесс (Typical workflow)

```
1. Старт сессии       → claude
2. Проверка контекста → /context
3. Режим плана        → Shift+Tab × 2 (для сложных задач)
4. Описание задачи    → Четкий, специфичный промпт (WHAT, WHERE, HOW, VERIFY)
5. Ревью изменений    → Всегда внимательно читайте diff!
6. Принятие/Отказ     → Enter / Esc
7. Верификация        → Запуск тестов и линтера
8. Коммит             → После завершения этапа
9. Сжатие (/compact)  → Когда контекст превышает 70%
```

## Управление контекстом (КРИТИЧЕСКИ ВАЖНО)

### Строка состояния (Statusline)

```
Model: Sonnet | Ctx: 89.5k | Cost: $2.11 | Ctx(u): 56.0%
```
**Следите за `Ctx(u):`** → >70% = `/compact`, >85% = `/clear`

### Пороги контекста

| % контекста | Состояние | Действие |
|-------------|-----------|----------|
| 0–50% | Зеленый | Работайте свободно |
| 50–70% | Желтый | Будьте избирательны в запросах |
| 70–90% | Оранжевый | Выполните `/compact` прямо сейчас |
| 90%+ | Красный | Необходим `/clear` |

### Реакция на симптомы

| Признак | Рекомендуемое действие |
|---------|------------------------|
| Слишком короткие или поверхностные ответы | `/compact` |
| Модель начинает "забывать" ранние договоренности | `/clear` |
| Контекст превысил 70% | `/compact` |
| Задача полностью решена | `/clear` перед новой задачей |

## Выбор модели и рассуждения (Thinking)

| Функция | Активация | Назначение |
|---------|-----------|------------|
| **Plan Mode** | `Shift+Tab × 2` или `/plan` | Исследование кодовой базы без изменения файлов |
| **OpusPlan** | `/model opusplan` | Opus для этапа планирования, Sonnet для реализации |

| Режим управления | Действие | Сохранение |
|-------------------|----------|------------|
| **Option+T / Alt+T** | Переключение thinking на поддерживаемых моделях | В рамках сессии |
| **Слайдер `/effort` или `/model`** | Выбор уровня усилий (low/medium/high/xhigh) | На модель или сессию |
| **`/effort max`** | Максимальные усилия рассуждения | Только текущая сессия |
| **`CLAUDE_CODE_EFFORT_LEVEL`** | Переопределение усилий в окружении запуска | На процесс |

### Быстрый выбор модели

| Задача | Модель | Уровень усилий (Effort) |
|--------|--------|-------------------------|
| Переименования, бойлерплейт, генерация тестов | Haiku 5.5 | `medium` (или `low`) |
| Разработка фич, отладка, рефакторинг | Sonnet 5.5 или Opus 5.5 | По умолчанию для модели |
| Архитектурные решения, аудит безопасности | Opus 5.5 (или Fable 5.2) | `high` / `xhigh` |

### Динамическое переключение моделей посреди сессии

**Паттерн**: Старт на Sonnet (скорость) → переключение на Opus (сложность) → возврат к Sonnet:

```bash
claude --model sonnet

# Встретилась сложная задача:
> "Реализуй OAuth2 PKCE-авторизацию с ротацией токенов"
/model opus                    # Переход к глубоким рассуждениям

# Реализация завершена, возврат к рутине:
/model sonnet                  # Оптимизация скорости и бюджета
```

## Создание собственных компонентов

```markdown
---
description: Краткое описание команды
argument-hint: "<обязательный_аргумент> [--флаг]"
disable-model-invocation: true
---
# Название команды
Инструкция, что необходимо выполнить...
Аргументы пользователя: $ARGUMENTS[0], $ARGUMENTS[1] (или $0, $1)
```

### Хук (Hook)
**Bash** (`.claude/hooks/my-hook.sh`):
```bash
#!/bin/bash
INPUT=$(cat)
# Обработка JSON из stdin
exit 0  # 0 = продолжить, 2 = заблокировать действие
```

## Формула эффективного промпта

```
WHAT:   [Конкретный ожидаемый результат]
WHERE:  [Пути к файлам или ссылки @file]
HOW:    [Ограничения, подход, стек]
VERIFY: [Критерии успеха, как проверять результат]
```

**Пример:**
```
WHAT: Добавить валидацию полей в форму авторизации
WHERE: src/components/LoginForm.tsx
HOW: Использовать Zod, отображать инлайн-ошибки под полями ввода
VERIFY: Пустой email показывает ошибку; невалидный формат показывает ошибку; тесты npm test LoginForm проходят
```

## Золотые правила работы с Claude Code

1. **Всегда проверяйте diff** перед нажатием Enter/подтверждением правок.
2. **Используйте `/compact`** до того, как контекст превысит 70%.
3. **Формулируйте четко**: модель лучше всего работает по схеме WHAT, WHERE, HOW, VERIFY.
4. **Используйте Plan Mode** (`Shift+Tab × 2`) для любых сложных или рискованных изменений.
5. **Создавайте `CLAUDE.md`** в корне каждого проекта.
6. **Делайте коммиты чаще** — после каждой успешно закрытой и проверенной подзадачи.
7. **Помните о приватности**: промпты, прочитанные файлы и вызовы инструментов отправляются в API Anthropic.

## Быстрое дерево решений

```
Простая задача        → Сразу пишите Claude
Сложная задача         → Tasks API или /plan для структурирования
Рискованное изменение  → Включите Plan Mode (Shift+Tab × 2)
Повторяющаяся задача   → Оформите в виде агента или команды (skill)
Контекст переполнен    → /compact или /clear
Нужна документация lib → Используйте Context7 MCP
Глубокий анализ кода   → Переключитесь на Opus (/model opus)
```

## Поиск по коду: выбор инструмента за 5 секунд

Точный текст → `rg` | Имя сущности → `rg` или `Serena` | Концепт/смысл → `grepai` | Синтаксис/AST → `ast-grep`

| Задача | Инструмент | Команда |
|--------|------------|---------|
| "Найти комментарии TODO" | `rg` | `rg "TODO"` |
| "Найти код авторизации" | `grepai` | `grepai search "authentication"` |
| "Кто вызывает функцию login?" | `grepai` | `grepai trace callers "login"` |
| "Получить структуру файла" | `Serena` | `serena get_symbols_overview` |
| "Поиск async без try/catch" | `ast-grep` | `ast-grep "async function $F"` |

# Модуль 03: Память и конфигурация (Memory & Config)

**Время**: 1 час | **Сложность**: ⭐⭐ Средний

**Предыдущий модуль:** [Модуль 02: Базовый цикл взаимодействия](02-core-loop.ru.md)

## Цель

Научить Claude Code помнить ваши предпочтения и специфичные правила проекта. Создать свой первый файл `CLAUDE.md`.

---

## Что вы узнаете

- Иерархия уровней памяти Claude Code
- Структурирование файлов инструкций `CLAUDE.md`
- Настройки и их приоритет (Settings Precedence)
- Инструкции и конфигурация на уровне проекта против глобальной

---

## Иерархия памяти (The Memory Hierarchy)

Claude Code считывает инструкции из нескольких файлов `CLAUDE.md`, двигаясь от самого широкого охвата к наиболее специфичному:

```
┌──────────────────────────────────────────┐
│ 1. ПОЛЬЗОВАТЕЛЬ (~/.claude/CLAUDE.md)    │
│    Применяется ко ВСЕМ вашим проектам    │
│    Пример: стиль кода, таймзона, язык    │
└──────────────────────────────────────────┘
                     │
                     ▼ (инструкции проекта загружаются следом)
┌──────────────────────────────────────────┐
│ 2. ПРОЕКТ (/your-project/CLAUDE.md)      │
│    Общий файл для всей команды в Git     │
│    Пример: стандарты команды, техстек    │
└──────────────────────────────────────────┘
                     │
                     ▼ (локальные заметки загружаются в конце)
┌──────────────────────────────────────────┐
│ 3. ЛОКАЛЬНО (/your-project/CLAUDE.local.md)
│    Ваши приватные заметки по проекту     │
│    В .gitignore, не коммитится           │
│    Пример: тестовые URL, песочницы       │
└──────────────────────────────────────────┘
```

В организациях также может настраиваться управляемая общекорпоративная политика (например, `/Library/Application Support/ClaudeCode/CLAUDE.md` на macOS).

### Правило объединения
Все применимые файлы загружаются и объединяются: более специфичный файл размещается после более общего. Они действуют как инструкции, а не принудительные настройки среды, поэтому избегайте противоречий между уровнями.

---

## Создание первого файла CLAUDE.md

`CLAUDE.md` — это обычный Markdown-файл в корне репозитория, фиксирующий правила работы.

### Базовая структура

```markdown
# Название проекта

## Назначение
Краткое описание того, какую задачу решает проект.

## Стек технологий
- TypeScript 5
- React 18
- Next.js (App Router)
- PostgreSQL / Prisma

## Стандарты кода
- Только функциональные компоненты React
- Все экспортируемые функции обязаны иметь явную типизацию
- Максимум 300 строк на файл
- Понятные имена переменных (никаких x, temp)

## Правила взаимодействия
- Всегда показывай diff перед подтверждением правок
- Используй /plan для любых ломающих изменений

## Команды разработки
- Тесты: `npm test`
- Линтер: `npm run lint`
- Сборка: `npm run build`
```

## Папка проекта `.claude/`

Настройки проекта хранятся в каталоге `.claude/`. Большая часть файлов предназначена для версионирования в Git, чтобы вся команда работала по единым правилам:

```
my-project/
├── CLAUDE.md                 (в Git — общие правила команды)
├── CLAUDE.local.md           (НЕ в Git — ваши приватные заметки)
├── .claude/
│   ├── settings.json         (в Git — общие настройки проекта, хуки)
│   ├── settings.local.json   (НЕ в Git — ваши локальные переопределения)
│   ├── agents/               (в Git — специализированные агенты проекта)
│   ├── skills/               (в Git — навыки и кастомные команды)
│   └── hooks/                (в Git — скрипты автоматизации)
```

В `.gitignore` добавляются только личные файлы:
```gitignore
.claude/settings.local.json
CLAUDE.local.md
```

> **Важно**: Не добавляйте в `.gitignore` всю папку `.claude/`, иначе вы скроете общие настройки, навыки и агентов от коллег.

## Файл settings.json

Для точного управления поведением создайте `.claude/settings.json` (общий) или `.claude/settings.local.json` (персональный):

```json
{
  "model": "opus",
  "autoCompactEnabled": true,
  "permissions": {
    "defaultMode": "default",
    "allow": ["Bash(npm test *)"]
  }
}
```

Основные параметры:
- **`model`**: какую модель использовать по умолчанию (`opus`, `sonnet` или полный ID модели)
- **`autoCompactEnabled`**: авто-сжатие при приближении к лимиту токенов
- **`permissions.defaultMode`**: режим разрешений сессии (`default` запрашивает подтверждение перед правками)
- **`permissions.allow` / `permissions.deny`**: правила белого и черного списков для инструментов

**Приоритет настроек (от высшего к низшему):**
1. Управляемые корпоративные политики (Managed Settings)
2. Флаги командной строки при запуске (`claude --model ...`)
3. `.claude/settings.local.json` (локальные переопределения разработчика)
4. `.claude/settings.json` (настройки проекта в репозитории)
5. `~/.claude/settings.json` (глобальные настройки пользователя)

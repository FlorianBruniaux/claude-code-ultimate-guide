# Модуль 07: Продвинутые паттерны (Advanced Patterns)

**Время**: 2–3 часа | **Сложность**: ⭐⭐⭐ Продвинутый

## Цель

Освоить оркестрацию мульти-агентных систем. Создавать комплексные пайплайны автоматизации, координирующие работу нескольких специализированных агентов.

---

## Что вы узнаете

- Архитектурные паттерны взаимодействия нескольких агентов
- Стратегии оркестрации (последовательная, параллельная, условная)
- Обработка ошибок, повторные попытки (retry) и безопасный откат (rollback)
- Шлюзы согласования (approval gates) для рискованных действий в продакшене

---

## Мульти-агентные системы

**Мульти-агентная система** — это архитектура, в которой несколько узкоспециализированных агентов взаимодействуют для достижения общей цели.

### Пример: Пайплайн выпуска релиза

Вместо того чтобы поручать одной общей сессии всю последовательность задач:

```
Вы: "Выпусти версию 3.5.0"
    ↓
    ├─→ [Version Agent] Обновляет файл VERSION и манифесты
    │
    ├─→ [Changelog Agent] Формирует список изменений на основе коммитов
    │
    ├─→ [Test Agent] Запускает полный набор тестов
    │
    ├─→ [Security Agent] Проводит сканирование безопасности
    │
    ├─→ [Docs Agent] Обновляет сопутствующую документацию
    │
    └─→ [Release Agent] Создает тег Git и готовит публикацию (после подтверждения)
```

Каждый агент сфокусирован на своей задаче, работает в чистом контексте и использует только необходимые инструменты.

---

## Паттерны оркестрации

### 1. Последовательный конвейер (Pipeline)
Агенты выполняются по очереди. Результат работы агента N передается на вход агенту N+1.
*Применение:* задачи с четкой зависимостью шагов (Парсинг ТЗ → Проектирование схемы БД → Генерация кода моделей → Написание тестов).

### 2. Параллельный веер (Fork-Join)
Несколько независимых агентов работают одновременно, после чего их результаты агрегируются в итоговый отчет.
*Применение:* независимые проверки (аудит качества + проверка безопасности + замер производительности).

### 3. Условная маршрутизация (Conditional Routing)
Анализатор оценивает входящую задачу и направляет ее соответствующему эксперту (баг безопасности → Security Agent, проблема со скоростью → Performance Optimizer).

---

## Обработка ошибок и надежность

### Мягкая деградация (Graceful Degradation)
Если один из неосновных агентов падает (например, сборщик документации), пайплайн не должен рушить всё, а формирует агрегированный отчет с предупреждением.

### Стратегия отката (Rollback Helper)
Для критических операций (релизы, миграции БД) создавайте явные bash-скрипты очистки, восстанавливающие состояние репозитория при падении любого шага:
```bash
git restore VERSION CHANGELOG.md
[ -n "$NEW_TAG" ] && git tag -d "$NEW_TAG"
```

### Шлюзы подтверждения (Approval Gates)
Перед деструктивными действиями (деплой в production) используйте хук `PreToolUse`, который переводит действие в режим явного запроса у пользователя (`"permissionDecision": "ask"`).

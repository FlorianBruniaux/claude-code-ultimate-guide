# Модуль 05: Навыки (Skills) и автоматизация

**Время**: 1.5 часа | **Сложность**: ⭐⭐ Средний

**Предыдущий модуль:** [Модуль 04: Агенты и специализация](04-agents.ru.md)

## Цель

Создавать проектные навыки (skills), которые передают Claude релевантные знания и повторяемые регламенты без постоянной загрузки их полного текста в контекст каждой сессии.

---

## Что вы узнаете

- Что такое навыки, когда и как они загружаются в контекст
- Правильная структура файла `SKILL.md`
- Как поле `description` управляет автообнаружением навыка моделью
- Как ограничивать вызов навыка пользователем и моделью (`disable-model-invocation`, `user-invocable`)
- Паттерн прогрессивного раскрытия информации (Progressive Disclosure)
- Как оценивать, тестировать и вовремя выводить навыки из эксплуатации

---

## Что такое навыки (Skills)?

**Навык (Skill)** — это отдельная директория, содержащая файл `SKILL.md` и сопутствующие вспомогательные материалы (скрипты, справочники). Модели анонсируется только краткое описание (`description`). Полный текст инструкций подгружается в диалог **только в момент вызова** — либо по вашей команде (`/имя-навыка`), либо когда текущий контекст запроса совпадает с описанием.

Это делает навыки идеальным инструментом для регламентов, чек-листов и стандартов, которые слишком объемны для постоянного хранения в `CLAUDE.md`.

### Сравнение механизмов

| Механизм | Лучше всего подходит для | Как загружается / выполняется |
|----------|--------------------------|-------------------------------|
| **`CLAUDE.md`** | Краткие факты и базовые правила для всех сессий | Загружается на старте сессии |
| **Skill (навык)** | Переиспользуемые знания, чек-листы, регламенты | Описание анонсируется; тело загружается при вызове |
| **Agent (агент)** | Изолированный контекст, выделенный набор инструментов | Работает в собственном отдельном контексте |
| **Hook (хук)** | Жесткие проверки, блокировки, валидация перед коммитом | Детерминированно выполняется кодом или шеллом |

## Создание первого навыка

Навыки располагаются в подпапках `.claude/skills/{имя-навыка}/`. Обязательным файлом является `SKILL.md`.

```text
my-project/
└── .claude/
    └── skills/
        └── testing-standards/
            └── SKILL.md
```

### Базовая структура `SKILL.md`

```markdown
---
name: testing-standards
description: Применяй соглашения Jest и React Testing Library проекта при написании, ревью или отладке тестов.
metadata:
  version: 1.0.0
---

# Стандарты тестирования проекта

## Когда применять
Используйте при создании юнит-тестов, тестировании компонентов, создании моков и фикстур.
Не используйте для E2E-тестов.

## Структура тестов
1. Arrange: подготавливайте минималистичные входные данные.
2. Act: вызывайте публичный интерфейс.
3. Assert: проверяйте поведение и видимый результат.

## Проверка
Запустите конкретный файл теста перед полным запуском test-suite.
```

## Управление обнаружением и вызовом

### Описание как маршрутизатор
Поле `description` должно четко указывать:
- Что делает навык
- В каких ситуациях его применять
- Анти-триггеры (когда навык применять НЕ следует)

### Ограничение доступа к вызову

```yaml
# Только ручной вызов пользователем через слэш-команду (для деплоя, коммитов, релиза):
disable-model-invocation: true
```

```yaml
# Только для модели (фоновые знания, без создания слэш-команды в UI):
user-invocable: false
```

```yaml
# Предодобренные инструменты на шаг вызова навыка:
allowed-tools: Read Grep Glob Bash(npm test *)
```

## Прогрессивное раскрытие информации (Progressive Disclosure)

Старайтесь держать `SKILL.md` компактным (до 500 строк), вынося громоздкие детали во вспомогательные файлы:

```text
testing-standards/
├── SKILL.md
├── references/
│   ├── mocking.md
│   └── integration-tests.md
└── scripts/
    └── select-tests.sh
```

Claude прочитает вспомогательные файлы из папки `references/` только тогда, когда это действительно потребуется для решения задачи.

## Чек-лист готовности к следующему шагу

✓ Навык сохранен по пути `.claude/skills/{name}/SKILL.md`  
✓ В поле `description` описаны триггеры и анти-триггеры активации  
✓ Вы понимаете разницу между ручным (`disable-model-invocation`) и модельным вызовом  
✓ Вы протестировали вызов навыка в чистой сессии  
✓ Жесткие критические проверки вынесены в хуки или скрипты, а не оставлены на усмотрение промпта

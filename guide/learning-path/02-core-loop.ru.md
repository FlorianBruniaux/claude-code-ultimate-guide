│    - Читает связанные файлы (auth-test.js, config.js и т.д.) │
│    - Разбирает контекст ошибки                               │

## Как Claude исследует кодовую базу проекта

Claude не читает проект целиком — он **интеллектуально ограничивает область поиска (scope)**.

### Пример: вы просите «Fix the login bug»

Claude выполнит следующие шаги:
1. **Поиск слова "login"** по кодовой базе
2. **Обнаружение файлов**: `auth.js`, `login.js`, `auth-controller.js`
3. **Чтение этих файлов** в первую очередь
4. **Поиск вызовов** (где именно вызываются эти методы)
5. **Чтение тестов** (если они есть)
6. **Поиск конфигурации** (переменные окружения, константы)

Claude **НЕ читает**:
- `node_modules/` (исключаются автоматически)
- Полную историю `.git` (избыточный объем)
- Все файлы проекта подряд (слишком долго и нерационально)

### Совет практикам

Формулируйте контекст конкретно:
- ❌ *"Fix the bugs"* → Claude придется гадать, где проблема
- ✅ *"Fix the login bug in auth.js on line 45"* → Claude мгновенно откроет нужный фрагмент

## Контекст: ключевая концепция

**Контекст** — это объем информации, который модель удерживает в рабочей памяти одновременно. Контекстное окно конечно (1M токенов на большинстве актуальных моделей).

### Что расходует токены контекста?

```
Ваш промпт:            ~50 токенов
Ответ Claude:          ~500 токенов
Чтение одного файла:   ~2000 токенов на файл
История диалога:       накапливаемый объем токенов
```

### Мониторинг контекста: `/context`

Команда `/context` выводит цветную сетку содержимого контекстного окна (сообщения, файлы, вызовы инструментов, файлы памяти) и рекомендации по оптимизации.
- Много свободного места: работайте спокойно
- Заполнено на 50–70%: будьте избирательны при чтении объемных файлов
- Более 70%: выполните `/compact`

### Команда `/compact` — ваш клапан безопасности

Когда контекст начинает переполняться:
```bash
/compact
```

Что происходит:
1. Текущий диалог суммируется и сжимается
2. Длинная история заменяется компактным резюме
3. Контекст освобождается, позволяя продолжать работу в той же сессии
4. Можно передать уточнение: `/compact keep the auth decisions`

## Режимы: обычный, Plan Mode и уровни усилий (Effort)

Работу Claude определяют два независимых параметра: **режим разрешений (permission mode)** и **уровень усилий рассуждения (effort level)**.

### Обычный режим (Manual / Prompt-based)
Перед выполнением команд и изменением файлов Claude запрашивает ваше подтверждение.
Подходит для:
- Исправления точечных багов
- Небольших фич
- Локального рефакторинга

Переключение режимов разрешений выполняется клавишей **`Shift+Tab`**. Другие режимы: `acceptEdits` (авто-принятие правок файлов), `auto` (фоновый классификатор оценивает безопасность действий) и `bypassPermissions` (без подтверждений, только для CI/CD).

### Режим плана (`/plan`)
Claude исследует кодовую базу в режиме **только для чтения**, формирует пошаговый план и ждет вашего одобрения перед внесением любых правок.
Подходит для:
- Сложных архитектурных фич
- Рискованных изменений в ядре системы
- Рефакторинга нескольких модулей одновременно

**Пример:**
```bash
/plan Переведи систему аутентификации с сессий на JWT-токены
```

### Уровень усилий рассуждения (`/effort`) и `ultrathink`
Глубина размышлений модели управляется уровнем усилий:
```bash
/effort          # открыть интерактивное меню
/effort high     # уровни: low, medium, high, xhigh, max или auto
```

Высокие уровни усилий (`high`, `xhigh`) рекомендуются для:
- Поиска трудноуловимых багов
- Принятия архитектурных решений
- Анализа безопасности и аудита

Слово **`ultrathink`** в единичном промпте включает глубокие рассуждения (`xhigh`) только на этот конкретный шаг, не меняя глобальных настроек сессии.

## Формула идеального запроса: WHAT, WHERE, HOW, VERIFY

| Часть | Назначение | Пример |
|-------|------------|--------|
| **WHAT** | Конкретная цель | *"Исправь ошибку с null pointer"* |
| **WHERE** | Область поиска / файлы | *"в `src/auth/login.js`, строка 45"* |
| **HOW** | Ограничения и подход | *"не меняя сигнатуру публичного API"* |
| **VERIFY** | Критерий успешности | *"все существующие тесты в tests/ должны проходить"* |

**Пример правильного запроса:**
```
Исправь ошибку авторизации для email-адресов со знаком плюс (+)
WHERE: src/controllers/auth.js, строка 78 (регулярное выражение валидации)
HOW: Обнови регулярку, разрешив символ +, сохранив остальные проверки
VERIFY: Запусти npm test tests/auth.test.js — все тесты должны быть зелеными
```

## Управление сессиями

- Каждая сессия сохраняется локально.
- Возобновить последнюю сессию: `claude --continue`.
- Возобновить конкретную сессию: `claude --resume` или `/resume`.
- Откатить диалог или код назад: `/rewind` (или двойное нажатие `Esc`).
- Дать понятное имя текущей сессии: `/rename feature-auth-jwt`.

## Практическое упражнение: Полный цикл

### Задача: создание утилиты валидации email

1. **Сформулируйте запрос по формуле:**
```
Создай утилиту для валидации email-адресов
WHERE: в src/utils/validators.js
HOW: экспортируй функцию validateEmail(email), возвращай boolean, обрабатывай краевые случаи
VERIFY: напиши тесты в tests/validators.test.js
```
2. **Claude анализирует проект**, находит существующие валидаторы и структуру тестов.
3. **Проверьте diff**: изучите логику функции и тестовые сценарии.
4. **Примите изменения** или отправьте замечание на доработку.
